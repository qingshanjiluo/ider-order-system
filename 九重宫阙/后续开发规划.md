## 一、优先级原则（为什么是这个顺序）

1. **玩法承诺优先于内容数量**。"寿元只决定死亡与转世"是这游戏的立身之本，而寿元耗尽现在**只是悄悄死亡**（大限劫零实现）。补 100 条技能也救不了一个没有终局体验的循环。
2. **"实例可达性"优先于"定义数量"**。E6 的 82→130 之类指标，如果 `gongfa`/`pets` 表恒为 0，做了等于没做（不变量 3 禁幽灵数据）。
3. **验收由章程自定标准判**，不由我的感觉判：E1 要 50 并发守恒、E2 要攻击模拟脚本、E3 要 `sim-battle` 四段胜率、E9 要铁律(1)(2)(3)(4)、E10 要"纯 UI 走完关键闭环"。这些**目前全都没有**，是上线判定的真短板。
4. 每轮**只做能在预算内"读完→改完→验证→提交"的一件事**。宁可少做，不做未取证的东西。

### T0-1 大限劫：寿元耗尽改为触发劫难（E5 核心，L）
- **先定位**：`grep 'age >= ' / 'passAway' / 'lifespan'` 于 `src/services/**` 与 `src/routes/cultivation.js`，找出寿元耗尽的**唯一判定点**（不得凭空新增第二处，避免双写）。
- **改法**：`age >= cap` 时不再直接陨落 → 置 `character.tribulation = { stage:'pending', expires_at_game_year: age + 3 }`，给 3 游戏年内应劫窗口；进入一场 **Boss 战**（复用 `combat.startBattle`，敌人为 `buildMonsterFromTemplate` 挑选 `level_range` 匹配当前境界的高阶模板，或专用"大限劫"模板）：
  - 胜 → 续寿 `balance.LIFESPAN_YEARS[realm] × 0.10`（走 `yearsOfRatio`，禁绝对值），清 `tribulation`，写编年史 `type:'劫数'`（`chronicle.js` 已有该标签）；
  - 败/超时 → 陨落转世（沿用现有转世路径，若不存在则本任务必须一并落地，否则终局无出口）；
  - 应劫中禁止再触发第二次（幂等：以 `tribulation.stage` 为闸门）。
- **复用**：`realm.isTribulationRealm(realmName)` 已存在，用它决定应劫强度（化神及以上才有"劫"，以下只是"寿尽"）。
- **验收断言**（新增"大限劫期"到 `scripts/test-content.js`）：
  1. `age = cap` 时角色**未死亡**且 `tribulation.stage === 'pending'`；
  2. 连续两次结算不产生两个 pending（幂等）；
  3. 胜利分支寿元增量 = `cap × 0.10`（比例制断言，禁绝对值常量）；
  4. 失败分支走转世且不可回滚；
  5. `大限劫` 关键字在 `src/` 命中数 > 0（反向锁住"零实现"这一状态不得复发）。

## 八、风险登记（已知，别踩）

1. **测量法造成的假阴性**（本会话已犯 5 次）：`grep include` 过滤、两套品质词表、把 JSON 字符串当对象取属性、单样本以偏概全、静态解析未拼前缀。**规则**：断言"不存在"前换一种查法交叉验证；断言"普遍"前全量统计；探针必须改**真正被读取的那个字段**。
2. **`node -e` 的双引号会被传输层剥掉** → JS 内一律用反引号字符串，或把逻辑写成临时脚本（跑完即删）。
3. **门禁命令不得接 `Select-Object -First N`**（会掐断子进程、`$LASTEXITCODE` 失真）→ 先 `> 文件`，取退出码，再看内容。
4. **PowerShell 字符串里塞裸双引号**（`Add-Content -Value`）反复炸；已改用单引号 here-string `@' … '@`。
5. **`Start-Process -RedirectStandard*` 在本机触发 `NO_PROXY` 字典冲突**；`ForEach-Object -Parallel` 触发沙箱 `spawn EPERM` → 并发测试要换写法（进程内 Node `http` 并发即可，轮 19 已验证可行）。
6. **超时残留进程**：一次 120s 超时后确实可能留下占着 `data/game.db` 的 node；复跑前先 `Get-CimInstance Win32_Process -Filter "Name='node.exe'"` 按**监听端口**判身份（3080 是 DSH 宿主，绝不可杀）。
7. 工具预算长期透支：**不要在无法整读的文件上动手**，这是 30 轮里唯一稳定的零返工来源。
