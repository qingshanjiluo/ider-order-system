### 1.2 玩法内核（本作的真正特色，必须围绕它做设计）

```
现实 24 小时 = 游戏 10 年（在线离线 100% 折算，settleTime）
寿元曲线：凡人100 → 炼气200 → 筑基500 → 金丹1500 → 元婴5000 → 化神2万
         → 炼虚5万 → 合体10万 → 大乘30万 → 渡劫100万（封顶）→ 飞升=超脱
寿元耗尽 = 坐化转世（passAway）：
  保留 成就/图鉴/VIP/点券/转世记忆 + 灵石30% + 仓库随机50%
  清空 境界/等级/修为/装备/功法/技能/灵宠/寿元奖惩
  转世计数 reincarnation_count + 1
熟练度 10 阶（无→学徒→…→道主），next(level)=100×level^1.6，每级 +2% 成功率（道主 +18%）
```
证据：`src/services/gameTime.js` 全文、`src/services/proficiency.js` 第 6-26 行。

**设计结论**：这是一款**"以一生为单位的 Roguelike 修仙人生模拟 + 放置"**。因此一切系统的产出价值必须二选一：
- **A 类（当世效率）**：提升本世的修炼/战斗/生产速度；
- **B 类（跨世传承）**：死亡后仍生效（图鉴、成就、称号、熟练度、道行、传承特权）。
> 现状缺陷：B 类只有"成就/图鉴/VIP/熟练度"，**转世缺乏主动决策与成长感**（灵石-70%、仓库-50% 是纯惩罚）。→ 见 §7.1 传承系统立项。

## 第二部分 · 架构决策（AD-xx，实施前定案）

**AD-1 持久化：分集合增量写 + 角色级互斥 + 写队列**
- 现状全量重写不可控。改为：`store` 维护 `dirtyCollections:Set<string>`；`saveDatabase()` 只序列化脏集合；写动作投递进**单消费者串行队列**（Promise 链），保证同一时刻只有一个写事务。
- 角色级互斥：`withCharacterLock(characterId, fn)`（Map<id, Promise> 链式排队）。所有修改角色/背包/灵石/寿元的端点必须包裹。
- 关键多实体写（锻造扣料+发成品、突破扣寿元+升境界）必须**先算后写**：先在内存完成校验与全部变更，再一次性标脏落盘；失败即丢弃副本重载。
- 验收：并发压测脚本 `scripts/concurrency-test.js`：同角色 50 并发 `/character/spend` → 余额精确；锻造 20 并发 → 材料不会负数、成品数量守恒。

**AD-2 单写者约束**：SQLite 全量镜像模式下 **PM2 必须 `fork` 模式 instances=1**，多核靠 cluster 会直接损坏数据。水平扩展的前提是先换 PG（见 AD-3），不可先扩进程。

**AD-3 迁移触发线（明确阈值，而非"以后再说"）**
```
触发任一即启动 PostgreSQL 迁移：
  DAU > 300  或  saveDatabase 平均耗时 > 80ms  或  事件循环 p99 延迟 > 250ms
  或  需要 ≥2 个写实例（分区服/跨服）
迁移设计：col_* → JSONB 表 + 关系表保持不变；store 层加 driver 抽象（sqlite/postgres），
按 character_id 分片（game.db 导出 → COPY）。预留 store 接口已在 REL_TABLES 一侧抽象，成本可控。
```

**AD-4 战斗技能唯一真源**：`db.player_skills` 成为主动技能源；`db.gongfa` 退居"被动/功法特效 + 元素亲和 + 熟练度载体"。迁移：以 `item_id` 映射 `SKILLS_DATA` 与 `skill-expansion` 的 `exp_*` id，新增 `player_skills.{cooldown_left, level, element, multiplier, mp_cost}`。
> 兼容：`/battle/skills/learn` 保留，内部改为"学功法 → 授予其绑定主动技"双写，保证老客户端不破。

**AD-5 数值单点化**：新建 `src/config/balance.js`，所有可调常量集中（伤害系数/寿元/掉落/价格/成功率），各模块 `require` 之。目标：**改一个数，全链路一致**；模拟脚本读取同一份。

**AD-6 数据规范**：每个内容品类 = `src/data/<cat>-library.js`（纯定义，无 IO）+ `services/<cat>-seed.js`（幂等播种）+ `scripts/validate-content.js` 断言。禁止再出现"目录里有、库里没有"的幽灵数据（七期已发生过一次）。

**AD-7 时间语义**：游戏时间是核心资源。所有"耗时行为"必须显式记账并写入编年史：闭关（可配年数）、渡劫、远行秘境、炼丹（炉次）。新增 `character.time_settled_at` 之外补 `character.last_action_game_year`，用于"某年做了某事"的传记密度。

## 第三部分 · 战斗系统重构（T-100 系列，最高优先）

### 3.1 目标战斗循环（回合制，10 回合内分胜负为设计基准）

```
参战单位 = 主角 + 1 出战灵宠（合击） vs 怪物（1-3 只，按地图难度）
每回合：
 1) 先手判定  first = speed_a*rand(0.85,1.15) vs speed_d 同式
 2) 行动：普攻（免费）或 主动技（需 MP≥mp_cost 且 cd=0）或 防御（本回合受伤×0.5，回 MP×1.5）或 逃跑
 3) 结算状态（灼烧/中毒/冰冻/眩晕/护盾）→ 扣血
 4) 回灵：MP += 5 + soul*0.25（soul=神识）；眩晕者跳过行动
 5) CD 递减
```

### 3.2 伤害公式定案（替换现有 `attack*2 - defense*0.8`）

```
K          = 60 + 8*attacker.level                 防御饱和常数
mitigation = defender.defense / (defender.defense + K)      ∈ [0,1)
raw        = attacker.attack * 2 * skillMult * (1 + 0.1*(skillLevel-1))
element    = 1.3 / 1.0 / 0.7（七系相克，沿用 elements.effectiveness）
crit       = rand < crit_rate ? crit_damage(默认1.5, 可装被抬到2.0) : 1
random     = rand(0.92, 1.08)
damage     = max(1, floor(raw * (1-mitigation) * element * crit * random))
```
理由：现式在 `def ≥ 2.5*atk` 时退化为保底 1（同境界坦克必胜），乘法减免保证收益递减且永不归零。

### 3.3 技能数值总表（写进 `balance.js`，并回填 214+技能）

| 项 | 规则 |
|---|---|
| 倍率 | 黄阶 1.10-1.35；玄阶 1.40-1.70；地阶 1.75-2.10；天阶 2.15-2.60；圣阶 2.70-3.30；仙阶 3.40-4.20 |
| MP 消耗 | 凡 `10+tier*4`；群体 ×1.8；持续效果技 ×1.4；CD 每 +1 回合，MP ×1.12 |
| 冷却 | 黄 2 / 玄 3 / 地 3 / 天 4 / 圣 5 / 仙 6（回合） |
| 槽位 | `slotMax = min(2 + realmIndex, 8)`（炼气 2 槽 → 飞升 8 槽）|
| 状态 | 灼烧(DOT 8%/回合×3)、中毒(DOT 5%×5)、冰冻(跳过1回合，PvP 减半)、眩晕(跳过1回合，仅 BOSS 抗性)、护盾(吸收 atk×1.2 伤害) |
| 灵宠 | 同元素主角→合击 +12% 伤害；异元素→独立出手（伤害 = pet.attack×1.1）|
| 逃跑 | `0.45 + (speed差)/120`，失败本回合不行动；BOSS 副本不可逃 |

### 3.4 战斗奖励与掉落（统一到一个函数）

```
exp   = floor(monsterLv*12*(1+difficulty*0.25) * (1+0.05*(越级数 clamp -20..20)))
stone = floor(monsterLv*3*(1+difficulty*0.3))
drop  = 每个 monster.drops[i]：rand < rate * map.drop_rate * (1 + luck*0.002)
保底  = 连续 20 场零掉落 → 第 21 场强制最高档掉落（pity 计数器存 character.drop_pity）
```

## 第四部分 · 成长与经济数值总表

### 4.1 等级—经验—境界（替换线性成长）

```
expToNext(level) = floor(60 * level^1.85)          level 1→100
境界门槛 = realm.min_level（沿用 realm.js 10×10 段表），但 exp_requirement 改为"境界累计经验"：
  累计到境界末期 → 触发可突破（canBreakthrough 同时校验 exp 与瓶颈材料）
瓶颈材料（新增，制造 A 类目标）：
  筑基=聚灵草×20+灵石2k | 金丹=丹霞果×5+筑基丹×1+灵石20k
  元婴=紫猴花×8+凝婴丹×1+灵石80k | 化神=玉髓芝×10+化神丹×1+灵石300k
  炼虚及以上=新增高阶灵植 + 天材地宝（见 §6 材料表）
```

### 4.2 突破概率（把"随机失败"做成可经营的赌局）

```
P = clamp(base − failures*5 + bonuses, 5, 95)
base: 炼气90 筑基80 金丹70 元婴60 化神50 炼虚40 合体32 大乘25 渡劫18 飞升10
bonuses: 破境丹+15 | 聚灵阵+8 | 洞府灵脉(lv×2) | 突破符+10 | 天道庇护(连续失败≥3，每次+6)  ← 保底心态设计
失败惩罚: breakthrough_failures+1 | 扣寿元 = max(20, 剩余寿元×3%) | 道基受损 debuff(3日内 P −10)
```
> 现实现只做了 `100 - failures*?` 的减法（realm.js 第 29 行），无正向可经营性 → 本节为其补上。

### 4.3 寿元经济（本作独有的核心循环，必须量化）

| 行为 | 寿元成本 | 期望收益 | 设计意图 |
|---|---|---|---|
| 闭关 1 年 | 1 年 | 经验 = 修炼速率×3 | 加速但折寿 |
| 闭关 10 年 | 10 年 | 经验×32（微超线性）+ 一次顿悟判定 | "赌一把大突破" |
| 历练/战斗 | 0 | 战利品 | 不折寿，效率低（保持挂机） |
| 秘境探索 | 0.5-3 年/层 | 高价值掉落 | 用寿命换机缘 |
| 炼丹/锻造 | 0 | 产物 + 熟练度 | 生活线不折寿 |
| 延寿丹 | − | +20/+100/+500/+2000 年（四档） | 顶级丹药的锚定价值 |
- 边际规则：单次延寿超过当前境界剩余寿元的 50% 时**减半**（防堆叠溢出，`gameTime.LIFESPAN_CAP` 已有总封顶）。

### 4.4 经济总账（防通胀，先定收入再定价格）

```
基准：1 现实日 = 10 游戏年 = 玩家"一世"的约 1/20（炼气 200 年寿）
目标：练气期日净收 5k-15k；筑基 30k-80k；金丹 150k-400k（跟随产出曲线，不失控）

收入端（每日满效率估算）：
  挂机修炼    : spirit_stone_per_second × 86400 × 0.35（活跃折算）
  采集        : (3 + map.min_level*0.4) × 次数上限(50)      ← 新增每日次数上限，防无限刷
  战斗        : monsterLv*3*(1+diff*0.3) × 上限(200)
  副本        : rewardsFor(dungeon) × 首通 + ×0.3 × 日常(5次)
  市场税      : 平台抽水（见下）→ 唯一硬回收阀
支出端：
  学技能/功法 : 100 × tier^2 × 境界系数
  锻造        : 材料成本 ×1.3（含 30% 失败损耗，失败返还 40%）
  炼丹        : 药材成本 ×1.5（炸炉损耗 15% → 丹炉等级降低）
  突破        : §4.2 瓶颈材料
  洞府/灵脉   : 升级指数 1.9^n
  市场税      : 成交价 8%（挂单 0，成交即扣）；每日挂单上限 20
定价函数（统一，写入 balance.js）：
  材料  price = TIER_PRICE[t] × (role==='main'?1.5:1.0)          // 20/80/300/1200/5000
  装备  price = 200 × 4^(qualityIdx) × slotMult(weapon 1.3/armor 1.0/accessory 0.9)
  丹药  price = 已定表（凡60 → 道40000）
  图纸  price = 材料合成成本的 60%（鼓励直接买材料锻造，图纸是"知识付费"）
  指导价: /market/rates 暴露 7 日成交均价中位数；偏离指导价 ±40% 的挂单直接拒绝（防对倒洗钱）
```
- 验收：`scripts/sim-economy.js` 模拟 30 世，输出每世"收入/支出/净差/峰值余额"，断言净差 / 收入 ∈ [−15%, +25%]（既不为零花钱发愁，也不无限膨胀）。

```
日志：结构化一行 JSON（ts/level/route/user/status/ms），按日切分，error 单独文件；
     启动时打印 banner（现有）+ 播种统计（materials.ensureAll 返回值）

     物品守恒失败、概率分布 3σ 偏离、坐化率异常（数值崩盘前兆）
```

### 9.4 安全加固清单（D8 相关，上线前必做）
1. `app.set('trust proxy', 1)`；限流改**双层**：IP 600/min + 用户 120/min + 敏感端点（突破/渡劫/交易/锻造）10/min。
2. 限流状态改 LRU + 上限 key 数（防内存无限增长）；命中返回 `Retry-After`。
3. 密码：bcrypt 保留，补 `cost≥10` 断言 + 登录失败计数与锁定（5 次/15 分钟）。
4. JWT：`JWT_SECRET` 强制环境变量；access 2h + refresh 30d（新端点轮换）；`sub` 校验角色归属（当前多处 `user_id` 反查，保留但统一走 `requireOwnedCharacter(req)` 助手）。
5. CORS：生产白名单域名；`express.json({limit:'64kb'})`；补 `X-Content-Type-Options`、`Referrer-Policy`、CSP（含 `connect-src 'self' wss:`）。
6. 输入校验：新建 `src/middleware/validate.js`（声明式 schema，替代散落 if），整数/字符串/枚举集中定义。
7. AI 生成内容：审核队列（`ai_generations.status`）+ 敏感词表 + 限次（免费 3/日，VIP 10/日，扣点券）。
8. 管理端：`/api/admin/*` 增加二次口令 + 操作审计表 `admin_audit`（现有 admin.js 262 行，改造成本低）。
