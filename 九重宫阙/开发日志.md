## 阶段 1 · SQLite 迁移 ✅（2026-09-11 完成）

### 架构决策
- **驱动**：Node 24 原生 `node:sqlite`（DatabaseSync）——零新增依赖，无编译链风险
- **模式**：兼容层方案。33 个路由的 `loadDatabase/saveDatabase/getNextId` API **一行不改**，
  底层替换为「进程级内存镜像 + 事务落盘」：
  - 镜像常驻进程 → **根除旧 100ms TTL 跨引用丢失更新的并发灾难**（阶段0 修复的根治版）
  - `saveDatabase` 即时事务落盘「有变化的集合」（JSON 快照 diff，行级 doc_id+JSON）
  - 安全网：20s 脏检查自动落盘 + SIGINT/SIGTERM/exit 钩子强制落盘
- **schema 按 v2 全量预建**：10 张关系表就绪（sects/sect_members/sect_buildings/sect_posts/
  guild_build_queue/lifespan_events/market_listings/market_orders/market_rates/ai_keys/ai_generations），
  阶段 4/6/8/9 直接使用，无需二次迁移
- 任意数组集合动态建表 `col_<name>`（doc_id + JSON 文档 + 索引）
