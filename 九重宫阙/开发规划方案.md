#### 4.1 数据库优化 (3天)
```sql
当前问题:
- SQLite 文档集合用 JSON 字段存储 (查询效率低)

-- 1. 为高频查询字段建索引
CREATE INDEX idx_char_user ON col_characters((json_extract(data, '$.user_id')));

  character_id INTEGER PRIMARY KEY,

  -- 常用字段展开，避免 JSON 解析

-- 3. 查询缓存
实现 Redis 作为查询缓存层 (可选，先用内存LRU)

实施:
```

#### 4.2 并发安全 (2天)
```javascript
当前问题:
- loadDatabase() + 修改 + saveDatabase() 非原子
- 无事务保护 (灵石扣除/道具发放可能不一致)

修复:
// 1. 数据库操作原子化
function withTransaction(fn) {
  const db = loadDatabase();
  try {
    const result = fn(db);
    saveDatabase(db);
    return { ok: true, data: result };
  } catch (e) {
    // rollback (重新 load)
    return { ok: false, error: e.message };
  }
}

// 2. 关键操作加锁
const locks = new Map(); // characterId → Promise
async function withLock(characterId, fn) {
  while (locks.has(characterId)) await locks.get(characterId);
  const promise = (async () => {
    try { return await fn(); }
    finally { locks.delete(characterId); }
  })();
  locks.set(characterId, promise);
  return promise;
}

实施:
- 所有修改character的路由包裹 withLock
- 测试: 并发修改同一角色 (灵石、经验)
```

```bash
#!/bin/bash
# backup.sh - 每日 3AM 执行

DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_DIR=/backups

# 1. 数据库备份
sqlite3 /data/game.db ".backup $BACKUP_DIR/game_$DATE.db"

# 2. 压缩
gzip $BACKUP_DIR/game_$DATE.db

# 3. 上传到对象存储 (可选)
# aws s3 cp $BACKUP_DIR/game_$DATE.db.gz s3://backups/

# 4. 清理30天前备份
find $BACKUP_DIR -name "game_*.gz" -mtime +30 -delete

# 恢复流程
# 1. 停服
pm2 stop jiuzhong-api

# 2. 恢复数据库
cp /backups/game_20250115_030000.db.gz /tmp/
gunzip /tmp/game_20250115_030000.db.gz
mv /tmp/game_20250115_030000.db /data/game.db

# 3. 启动
pm2 start jiuzhong-api
```

4. **风险可控**: 每个环节都有备份方案

3. 搭建基础监控，为后续优化提供数据支撑
