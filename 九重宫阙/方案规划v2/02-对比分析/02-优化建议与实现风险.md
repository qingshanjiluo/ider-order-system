## 一、关键设计缺口补全

### 1.1 寿命机制的两个未定义交互（最高优先级）

**缺口 A：寿元耗尽的终局**
三种候选模型：
- **坐化转世（推荐）**：寿元耗尽 → 角色坐化 → 转世重开。保留：熟练度等级、图鉴/成就、仓库部分资产、称号；清空：境界/修为/装备。形成 roguelite 循环，与"飞升"终极目标呼应（飞升 = 跳出轮回）
- **锁定状态**：无法修炼/战斗，仅能靠延寿手段续命（温和但可能造成"僵尸号"体验）
- **直接死亡删号**：最硬核，但付费玩家流失风险大

**缺口 B：离线挂机是否推进年龄**
- 现有挂机离线上限 250 小时 ≈ **104 游戏年**——凡人（100 年）挂机一次即寿终
- 建议：**离线时间按 25% 折算寿命推进**（250h 离线 ≈ 26 游戏年），或离线只产出收益不推进年龄。必须二选一明确

**建议的寿命-境界绑定曲线草案**（24h=10年口径）：

| 境界 | 寿元上限 | 现实时间约合 |
|---|---|---|
| 凡人（出生） | 100 年 | 10 天 |
| 炼气 | 150 年 | 15 天 |
| 筑基 | 200 年 | 20 天 |
| 金丹 | 300 年 | 30 天 |
| 元婴 | 500 年 | 50 天 |
| 化神 | 800 年 | 80 天 |
| 渡劫 | 1200 年 | 120 天 |
| 大乘 | 2000 年 | 200 天 |
| 飞升 | 5000 年+ | 500 天+（脱轮回） |

> 延寿丹药/功法在此之上做加法。该曲线让"突破"有了真实的生存意义——境界不仅是战力，是命。

### 1.2 经济粒度

- **存储方案**：单一整数字段，以**下品灵石为基本单位**（JS 安全整数 2^53 ≈ 9×10^15 下品，1 极品=10^9 下品，全灵石资产可无损表示）
- **显示层**：万/亿/兆 缩写；4 品阶灵石作为**物品形态**存在，可通过官方兑换（1000:1）互相转换
- **待确认**：兑换是否双向、是否收手续费（见问题 8）
- 1:1 兆的上界灵石**不建议**进入常规货币流通，作为收集/消耗品处理

### 1.3 技能 CD 翻倍的实现口径

- 建议：`实际CD = 基础CD × 2^(max(0, 装备数-5))`——6 技能全部 ×2，7 技能 ×4……10 技能 ×32
- key 技能（多轮必放）不受 CD 惩罚影响，作为"第 6-10 格仍然值得带"的理由
- 技能格解锁建议与境界/资质挂钩，与"动态解锁 3→10"吻合

### 1.4 副修功法与神魂/分魂

- 神魂强度决定**副修槽位数**（1-5）与**每个副修的效率百分比**
- 建议公式：`副修i效率 = 神魂系数 × 分魂i品质`，总和不超过主修的 50%（防主副倒挂）
- v1 的"战斗功法 2 个"分类**取消或并入**技能系统（待确认，见问题 5）

## 二、架构建议

### 2.1 AI 系统架构（核心建议：数值程序化，文案 AI 化）

```
┌─ 管理后台 ──────────────────────────────┐
│ 密钥池（主/备×N，按功能映射模型，定时测速）  │
│ 内容审核池（AI 产出 → 人工/规则审核 → 入库）│
└────────────────────────────────────────┘
            ↓ 异步任务队列
┌─ 生成执行层 ────────────────────────────┐
│ 数值框架（程序生成，保证平衡）              │
│ + AI 填充（名称/描述/文案/风味文本）        │
└────────────────────────────────────────┘
```

- **铁律**：AI 永远不直接产出数值。器方/丹方/功法的数值由程序按品阶模板生成，AI 只负责命名、描述、风味词条
- **顿悟创功法**：触发条件（熟练度+流派极高）→ 程序按流派模板生成数值框架 → AI 起名写描述 → 入审核池 → 下次维护入库。玩家感知是"我创了功法"，系统风险为零
- **密钥池容灾**按设计图实现：功能→模型映射、测速失败自动切换、全不可用则功能显式报错（不静默降级到假数据）
- 无匹配配方时"概率炼出全新配方"：先用**程序概率**判定触发，再走上述生成管线

### 2.2 宗门 UGC 治理

- 玩家创建宗门的名称/简介：敏感词过滤 + AI 复审
- 自定义功法/技能：**只能从模板库选择 + 参数滑块**（限制在平衡区间），不允许自由输入数值
- 特殊地图怪物：**从现有怪物库组合**（选择+数量），不允许自由创造怪物
- 入门要求：从预设条件集合选择（境界/灵根/贡献等）

### 2.3 数据层前置结论

v2 的内容密度（词条/器灵/契约/双贡献/4级灵石/宗门/寿命编年史）使 JSON 文件存储**彻底不可行**。结论：
- **SQLite 迁移必须排在 v2 内容开发之前**（路线图调整：P0 修复 → SQLite 迁移 → v2 系统）
- 寿命/编年史需要时间序列数据（按游戏年记录事件），SQL 天然适配

### 2.4 交易行复用

工单系统已有 `market_listings` / `market_orders` / `market_purchases` 成熟实现（挂单/购买/审核流），拍卖所可直接借鉴其模式；市场调控浮动面板建议简化版：**系统商店价格 = 基准价 × 供需系数（±30% 封顶）**，由全服产出/消耗统计驱动。下注/抽奖/老虎机作为独立娱乐模块，**不与付费点券直接挂钩**（见问题 10）。

### 2.5 前端导航重组

12 主导航 + 二级菜单（见 12-面板导航设计）替代现有 27 平铺 tab；前端反正要大改（P0 修复清单），建议同步落地新导航骨架。

## 三、数值骨架草案（待确认后细化）

### 3.1 熟练度 10 级曲线

`升级所需操作次数 = 50 × 1.8^级`（学徒 50 次 → 主宰 约 5000 万次——主宰应为服务器级荣誉，极少数人达成）

| 级 | 名称 | 累计操作次数（约） |
|---|---|---|
| 1 | 学徒 | 50 |
| 2 | 工匠 | 140 |
| 3 | 精通 | 400 |
| 4 | 大师 | 1,100 |
| 5 | 宗师 | 3,200 |
| 6 | 大宗师 | 9,200 |
| 7 | 无上大宗师 | 27,000 |
| 8 | 道主 | 78,000 |
| 9 | 主宰 | 226,000 |

（注：1.8^9 累计约 22.6 万次，配合 n/时 挂机练习，2-3 个月日徽可满级一位，主宰留给肝帝。数值待数值设计阶段再精调。）

### 3.2 超品概率模型草案

`纹数期望 = f(熟练度等级, 材质总品阶分, 催化数)`
- 基准：1 纹保底判定线随熟练度提升；每 1 催化 +8% 超品概率、+5% 期望纹数
- 5 纹（超品满）仅宗师+满配可达，全服稀有

### 3.3 灵根-特殊灵根映射草案

| 特殊灵根 | 对应流派 | 被动方向（示例） |
|---|---|---|
| 剑 | 飞羽门/剑修 | 剑系技能伤害+、暴击 |
| 丹 | 长青圣地/丹修 | 炼丹成功率+、丹药效果+ |
| 欲 | 合欢宗/魅修 | 魅惑控制、双修加成 |
| 财 | 万界商城/商道 | 财运、交易税率- |
| 至尊 | 天道系 | 渡劫概率+、天道契合 |
| 炉鼎 | 特殊 | 双修/器灵相关特殊机制 |

（五行山"模拟全属性"= 玩家 3+ 灵根时把缺的元素用其他属性补足达成全克制；同阶无敌靠属性补正而非数值膨胀——具体数值待设计。）
